# 研究脉络

帮助读者理解“问题如何变化，每项工作改变了什么”。遵循共享成果规范与 evolution JSON 协议。

核对来源日期，明确使用首次发表日期还是当前 PDF 版本日期；统一口径。页面解析未提取到日期不代表论文没有日期。无日期证据的工作以并列研究线索呈现，period=null，不用参考文献年份推断，不强行排序。

每个节点只保留解释变化所需的事实，detail 用一个短段落，最多100字；不要把整张研究卡中的所有贡献和实验复制进节点。

每个节点的 period 给时间及口径，problem 给当时要解决的问题，improvement 说明该工作引入的变化，detail 解释变化如何实现，limitations 给仍未解决的边界。只把有原文依据的引用、继承、比较关系写成关系；先后或主题相近只是并列研究线索。

summary 交代脉络及时间口径，用一个短段落，不提前复述所有节点。现有协议中的 conditions 和 metrics 仅填写核对得到的必要背景，页面不再复制方法对比的整张指标表；缺少时用null并省略对应段落。不得为必填字段补造事实。

单篇或同一时间切片交付研究定位，明确无法支持跨时期演进。gaps=[]，不输出缺口清单；已核对的日期口径放导语。

完成标准：读者知道变化发生在哪个层面，能区分作者已证明的改进和本次对读推断，不会把时间线误认为传承链。
